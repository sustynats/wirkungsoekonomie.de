# Sprint 9 - Launch Decision

## Entscheidung

**SOFT GO**

## Begründung

Es gibt keine Blocker und keine schweren Mängel auf Kernseiten. Navigation, Footer, Sitemap, Robots, 404, SEO-Basis, OG/Twitter-Metadaten, Linkstruktur, Accessibility-Basis, rechtliche Hinweise, Tools und politische Sprachseite sind launchfähig.

## Warum Soft Go statt GO?

Einzelne Bereiche sind bewusst MVP oder Feinschliff:

- Kompass und Scanner sind MVPs.
- Rente und Wirkungseinkommen sind Modellrechnungen.
- Audio-Transkripte sind nicht vollständig.
- Archivbilder und alte LinkedIn-Importe bleiben erhalten, sind aber nicht Teil der primären Sitemap.
- Echte Datenanbindung des Scanners kommt später.

## Go-/No-Go-Kriterien

| Kriterium | Status |
|---|---|
| Navigation einheitlich | erfüllt |
| Scanner unter Anwendungen | erfüllt |
| Quellen öffentlich als Evidenz | erfüllt |
| Sitemap ohne Drafts/Audits/rejected | erfüllt |
| Robots schützt interne Bereiche | erfüllt |
| 404 professionell | erfüllt |
| SEO-Basis zentraler Seiten | erfüllt |
| Mobile Kernseiten | erfüllt |
| Accessibility-Basis | erfüllt |
| Rechtliche Hinweise | erfüllt |
| Politische Sprache geschützt | erfüllt |
| Audio/Natalie/Downloads erhalten | erfüllt |

## Empfehlung

Veröffentlichen als **Soft Go**. Danach keine breite Inhaltsausweitung, sondern:

1. Transkripte vervollständigen.
2. Archivbilder komprimieren.
3. Kompass/Scanner anhand echter Testfälle härten.
4. Datenschutz erneut prüfen, sobald Uploads, APIs oder URL-Analyse produktiv werden.
